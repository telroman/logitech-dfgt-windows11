# Logitech Driving Force GT у Windows 11 зі збереженням Memory Integrity

Практичні нотатки, стан на 23 жовтня 2026 року. Мета — native mode, незалежні педалі та керування в Need for Speed Unbound без повернення старого драйвера Logitech. Це опис перевіреної конфігурації одного комп’ютера, **не новий драйвер і не гарантія повної сумісності**.

На цьому комп’ютері раніше були драйвери Logitech, тому чисте встановлення Windows з нуля за цією інструкцією ще не перевірене. Залишки старого профілю впливали на діагностику. Повну віддачу цей спосіб поки не відновив.

## Що вдалося перевірити

| Частина | Фактичний результат |
| --- | --- |
| Захист Windows | Memory Integrity залишалася увімкненою; `SecurityServicesRunning` містить `2` |
| Фізичне кермо | USB/HID Logitech `VID_046D`, native `PID_C29A`, Microsoft `input.inf` |
| Перемикання режиму | Локальний скрипт переводив початковий `PID_C294` у `PID_C29A` |
| Кут | Для 360° повна вісь досягалася приблизно на ±180°; сильну автопружину вдалося вимкнути |
| Педалі | Газ Y і гальмо Z незалежні; у перевіреному DirectInput-поданні відпущено 65535, натиснуто 0 |
| x360ce | Газ → RT, гальмо → LT; кожна педаль незалежно дає 0 у спокої та 255 при повному натисканні |
| Unbound | Користувач підтвердив роботу газу, гальма й керма через віртуальний Xbox-контролер |
| Приховування | HidHide дозволяє x360ce читати фізичне кермо, приховуючи його від інших програм |
| Force feedback | **Не відновлено**; деталі та обмеження наведено нижче |

## 1. Безпечна початкова перевірка

1. Закрий гру та `joy.cpl`. Збережи свої поточні налаштування контролерів.
2. Відкрий «Створення точки відновлення» (`Utwórz punkt przywracania` у польській Windows), перевір захист системного диска та створи свіжу точку. Дочекайся підтвердження. У цьому випадку свіжа точка була підтверджена, а перед додатковими драйверами створено ще одну.
3. У «Безпека Windows → Безпека пристрою → Ізоляція ядра» залиш Memory Integrity увімкненою. За потреби стан можна прочитати з PowerShell від адміністратора:

   ```powershell
   (Get-CimInstance -Namespace root\Microsoft\Windows\DeviceGuard -ClassName Win32_DeviceGuard).SecurityServicesRunning
   ```

   Для цієї перевірки очікуємо, що список містить `2`. Відмова доступу не доводить, що захист вимкнений: перевір його у Windows Security.
4. Перевір стан керма та hardware IDs у Диспетчері пристроїв. Драйвер фізичного керма в робочій конфігурації — Microsoft `input.inf`. Не замінюй його старим Logitech навмання.

   ```powershell
   Get-PnpDevice -PresentOnly |
     Where-Object InstanceId -Match 'VID_046D&PID_C29[4A]' |
     Format-Table Status,FriendlyName,InstanceId
   ```

Самої назви «Driving Force GT» недостатньо для визначення режиму. Перевіряй PID. Перемикання та USB-підключення можуть спричиняти калібрувальний рух: звільни простір навколо обода.

## 2. Native mode та кут повороту

Завантаж ZIP репозиторію через Code → Download ZIP, розпакуй його та поклади чотири `.ps1` із кореня репозиторію в стабільну папку `C:\DFGT`. Переглянь їх перед запуском. Приклади нижче припускають саме цю папку. Оригінальний локальний `Switch-DfgtNative.ps1` збережено без змін.

Скрипт використовує HID-команди переходу `C294 → C29A`, а потім задає 900°. Він не встановлює старий драйвер Logitech. Звіт скрипта про знайдений пристрій або завершення надсилання **не замінює** перевірку нового PID та фізичної поведінки.

У звичайному Windows PowerShell, із закритою грою:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\DFGT\Switch-DfgtNative.ps1"
```

Після появи `PID_C29A` вибери потрібний загальний діапазон:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\DFGT\Set-DfgtRange.ps1" -Degrees 360 -AutoCenter Off
```

Для 360° очікуємо повний діапазон приблизно за пів оберту в кожен бік від центра. Для 900° — приблизно по 450° у кожен бік. Не долай силовий упор. Вимкнення автопружини прибрало надмірний постійний опір у перевіреному випадку; це не ввімкнення ігрової віддачі.

Повернення 900°:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\DFGT\Set-DfgtRange.ps1" -Degrees 900 -AutoCenter Off
```

`-AutoCenter On` повертає наявну автопружину без установлення її сили; попередній сильний опір може повернутися. Спочатку перевіряй кут без неї. `ExecutionPolicy Bypass` тут діє лише на запущений процес і не вимикає Memory Integrity.

## 3. Не плутай назви осей із призначеннями педалей

У свіжовідкритому `joy.cpl` по черзі перевір:

1. Обидві педалі відпущені.
2. Натиснутий тільки газ.
3. Натиснуте тільки гальмо.
4. Газ утримується наполовину, а гальмо натискається та відпускається.

Педалі мають рухати різні осі незалежно. У нашому випадку газ рухав вертикальний хрестик Y, гальмо — шкалу Z. Шкала гальма зменшувалася при натисканні. Назва `Accelerator` на шкалі сама по собі не доводить, що це газ.

Якщо після змін панель показує стару назву чи осі, повністю закрий вікно властивостей і сам `joy.cpl`, потім відкрий заново. В нашому випадку давно відкрита панель зберігала старі метадані, тоді як нові незалежні читання HID/DirectInput уже показували справні осі.

**Не повторюй експерименти з перестановкою осей у реєстрі.** Перевизначення HKCU/HKLM не виправило Unbound, а один тест спричинив постійний задній хід і втрату видимої реакції газу. Зміни відкочували з точкових резервних копій. Скидання профілю виконувалося лише для конкретного керма після резервування, із від’єднаним USB; це не стандартний крок для нового користувача. Якщо твій профіль справний, не скидай його і не імпортуй чужі `.reg`.

## 4. x360ce: виправлення призначень для Unbound

Оскільки в перевіреній конфігурації Unbound не вдалося нормально перепризначити фізичні педалі, використали шлях:

```text
DFGT / Microsoft input.inf → x360ce 4.x → віртуальний Xbox → Unbound
```

1. Завантаж x360ce тільки з [офіційного сайту](https://www.x360ce.com/) або [офіційних релізів](https://github.com/x360ce/x360ce/releases). Тут перевірявся x64 4.26.38.0. Зберігай програму в постійній папці, наприклад `C:\DFGT\x360ce`.
2. Для віртуального Xbox потрібний ViGEmBus. У цьому випадку використовувався офіційний [ViGEmBus 1.22.0](https://github.com/nefarius/ViGEmBus/releases/tag/v1.22.0), а для приховування — [HidHide 1.5.230](https://github.com/nefarius/HidHide/releases/tag/v1.5.230.0). Підписи інсталяторів перевірили як Valid / Nefarius Software Solutions e.U., хеші зіставили до встановлення. Обидва драйвери запустилися, а HVCI залишилася активною.
3. **ViGEmBus завершив життєвий цикл.** Це залежність конкретного перевіреного способу, а не обіцянка подальшої підтримки Windows. Прочитай [заяву розробника](https://docs.nefarius.at/projects/ViGEm/End-of-Life/) перед вибором цього шляху. Цифровий підпис сам по собі не гарантує майбутньої сумісності або відсутності вразливостей.
4. У x360ce додай **онлайн-пристрій DirectInput** DFGT до Controller 1. Не додавай одночасно його копію Raw Input або старий offline-пристрій. Увімкни відображення стану віртуального контролера.
5. Визнач осі фізичним натисканням. У перевіреному екземплярі x360ce вони відповідали `a1` = кермо X, `a2` = газ Y, `a3` = гальмо Z. На іншій конфігурації номери можуть відрізнятися.
6. У режимі виразів відповідних полів було збережено:

   | Поле Xbox | Перевірений вираз |
   | --- | --- |
   | Left Thumb X | `=a1` |
   | Right Trigger / RT — газ | `=1-a2` |
   | Left Trigger / LT — гальмо | `=1-a3` |

   Це формули конкретного перевіреного профілю. Якщо їхній результат відрізняється, спочатку перевір фактичну вісь та її діапазон. Не перенось формули сліпо на інші версії програми або інші колеса.
7. **До запуску гри перевір саме результат Xbox:** відпущений газ RT = 0, повністю натиснутий RT = 255; гальмо LT = 0…255. Друга педаль повинна залишатися на 0. Проміжний варіант із максимумом 128 був виправлений — такий результат не вважається повним ходом.
8. Збережи налаштування. Залиш x360ce відкритим під час гри; версія 4.x має працювати для віртуального контролера. Копіювання старих XInput DLL у папку Unbound для цього способу не потрібне.

Кнопки перевіряй окремо. Сам факт руху керма та педалей не підтверджує правильність усіх кнопок або віддачі.

## 5. HidHide: прибрати подвійний сигнал у грі

Вмикай приховування **після** успішної перевірки RT/LT. В іншому разі складно відрізнити помилку формули від втрати доступу до пристрою. Загальна процедура описана в [офіційній інструкції HidHide](https://docs.nefarius.at/projects/HidHide/Simple-Setup-Guide/).

1. Збережи поточний список прихованих пристроїв і дозволених програм, щоб мати відкат.
2. У Applications додай **точний повний шлях** до свого `x360ce.exe`.
3. Якщо використовуєш наведені скрипти, додай також `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`. Саме цей процес викликає автоперемикання та команду кута. Це дозволяє всім скриптам, запущеним цим виконуваним файлом, бачити приховане кермо, тому не додавай зайві програми. PowerShell 7 `pwsh.exe` — інший процес.
4. У Devices вибери тільки фізичний DFGT із `VID_046D&PID_C29A`. Не приховуй віртуальний Xbox, клавіатуру, мишу чи всі HID-пристрої. Ідентифікатор екземпляра береться з твого комп’ютера; чужий шлях не підходить.
5. Залиш inverse application mode вимкненим; увімкни приховування.
6. Закривши гру, перепідключи USB у той самий порт і дочекайся перемикання режиму. Повторно перевір у x360ce онлайн-стан та RT/LT.

Після приховування звичайна діагностична програма може вже не бачити фізичний DFGT — це очікувано. **x360ce повинен його бачити.** Якщо педалі в x360ce перестали реагувати, не змінюй формули: спочатку перевір дозвіл точного executable, перезапусти x360ce, а якщо це не допомогло — тимчасово вимкни приховування лише цього DFGT, перепідключи USB та віднови базову перевірку. Саме під час цього етапу в нашому випадку знадобилося повторне підключення та перевірка доступу.

Запускай Unbound лише коли віртуальні RT/LT працюють правильно. Користувач підтвердив, що після цього машина реагує на обидві педалі й кермо. Якщо гра не приймає віртуальний контролер, не обходь її захист — припини цей варіант налаштування.

## 6. Слабка реакція керма біля центра

За загального кута 360° узгодь налаштування діапазону x360ce з 360°. У перевіреному профілі використовувався прямий вираз `=a1`; мертва зона X у x360ce була 0. Це не підтверджує значення мертвої зони всередині гри.

На ранньому скріншоті Unbound було **Deadzone 22%**. Така зона може пояснювати слабку реакцію на невеликі повороти. Поточне значення не прочитане. Для перевірки вручну спробуй 2–5%, потім перевір стійкість біля центра; це рекомендація для тесту, а не вже виконана зміна. Не збільшуй механічний опір для виправлення мертвої зони.

## 7. Автоматичне перемикання після входу

Налаштовуй автозапуск лише після ручних перевірок. Всі чотири скрипти мають залишатися разом у стабільній папці: `Switch-DfgtNative.ps1`, `Set-DfgtRange.ps1`, `Watch-Dfgt.ps1`, `Install-DfgtAutoSwitch.ps1`.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\DFGT\Install-DfgtAutoSwitch.ps1" -RestorePointChecked
```

Інсталятор створює завдання `DFGT Native AutoSwitch` для поточного користувача з Limited-привілеями та запускає спостерігач. Якщо завдання вже існує, спочатку перевір його; не створюй дубль. При відмові доступу досліди причину, замість підвищення до SYSTEM.

Спостерігач раз на 10 секунд шукає `C294`; лише при його появі викликає перемикання, а потім 360° / AutoCenter Off. Якщо вже є `C29A`, повторного налаштування не виконує. Він працює, доки користувач увійшов у Windows. Зміна кута відхиляється, якщо процес Unbound виявлений. Журнал `AutoSwitch.log` зберігається поруч.

Отже, підключення вже у `C29A` не гарантує повторного застосування 360°. Якщо потрібно, закрий гру й застосуй команду діапазону вручну. У нашому випадку журнал підтвердив перехід режиму та надсилання 360°/Off після повторного підключення; повний цикл на чистій Windows ще не перевірений.

## 8. Чого поки немає: повноцінний force feedback

Власник пам’ятає повну віддачу зі старими драйверами Logitech, крім проблем педалей. Це важливий опис попередньої поведінки, але він не доводить її наявності в поточному Microsoft-профілі.

Факти поточних тестів:

- Короткі тести віддачі x360ce не дали відчутного фізичного руху. Після них тестові значення повернуто на 0, віддачу вимкнено.
- Свіжа перевірка справжнього DirectInput-пристрою дала flags `0x00000005`, тобто `DIDC_FORCEFEEDBACK=False`. Старі кешовані метадані x360ce могли показувати інше. Збільшення сили тесту не виправить відсутню підтримку ефектів у цьому шляху.
- Окремий слабкий прямий HID-імпульс на 250 мс і команда зупинки були прийняті Windows. Користувач повідомив, що помітного руху не було. Успішний запис не дорівнює роботі мотора.
- Через REA дослідили стару бібліотеку Logitech та підготували компонент формування команд. Він компілюється і проходить перевірки пакетів, але **не є готовим драйвером Windows, модулем DirectInput або інтеграцією з грою**. У систему його не встановлювали.

Можливий подальший напрям — новий користувацький модуль ефектів із Microsoft HID-драйвером, якщо вдасться підтвердити транспорт, життєвий цикл і аварійну зупинку. Необхідність нового драйвера ядра поки не доведена. Для нього потрібні окремі перевірки HVCI та належне підписування; це не вирішується простим патчем старого SYS. [Вимоги Microsoft щодо сумісності](https://learn.microsoft.com/en-us/windows-hardware/test/hlk/testref/driver-compatibility-with-device-guard).

В Xbox-режимі гра передає сигнали вібрації, а не обов’язково всі ефекти керма. Конвертація rumble, штучна пружина центрування та віддача від фізики шин — різні речі. Новий модуль не може відновити інформацію, якої гра не передає.

Прямі команди мотора до цієї покрокової інструкції не включено. Вони потребують контрольованих тестів з обмеженням сили та гарантованою зупинкою. Встановлювати старий Logitech або вимикати Memory Integrity для продовження не потрібно.

## 9. Відкат

1. Закрий гру. В HidHide зніми приховування **лише свого DFGT**, потім перепідключи USB. Якщо до досліду були інші приховані пристрої, збережи їхні налаштування.
2. Зупини x360ce: віртуальний Xbox більше не повинен керувати грою. Microsoft HID-драйвер фізичного керма залишається.
3. Вимкни автозапуск і зупини спостерігач:

   ```powershell
   Disable-ScheduledTask -TaskName 'DFGT Native AutoSwitch'
   Stop-ScheduledTask -TaskName 'DFGT Native AutoSwitch'
   ```

4. Якщо потрібно, із закритою грою поверни 900° наведеною вище командою. Інакше активний спостерігач після нового переходу режиму знову застосує 360°.
5. За потреби видали HidHide/ViGEmBus через «Встановлені програми», попередньо перевіривши, чи їх не використовують інші контролери або програми. Виконай потрібне інсталятором перезавантаження.
6. Не імпортуй чужі реєстрові резервні копії. Точку відновлення використовуй для відповідної системної проблеми; для простого вимкнення автозапуску або приховування достатньо точкових дій вище.

## Походження та межі публікації

Це знеособлений опис досліду, підготовлений для GitHub. Він не містить пропрієтарних DLL/SYS Logitech, токенів доступу, персональних USB instance IDs, реєстрових експортів чи скріншотів користувача. У корені репозиторію лежать копії чотирьох використаних скриптів перемикання, кута й автозапуску. Інструкція сама їх не завантажує, не встановлює й не запускає. Публічні копії не змінюють чинне завдання на ПК автора.

Формат команд кута звіряли з відкритою реалізацією [Linux lg4ff](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-lg4ff.c). Linux-драйвер у Windows не встановлюється. Інші джерела: [x360ce](https://www.x360ce.com/), [HidHide CLI](https://docs.nefarius.at/projects/HidHide/CLI-Usage/), [Memory Integrity / Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/bringup/device-guard-and-credential-guard), [DirectInput effect driver API](https://learn.microsoft.com/en-us/windows/win32/api/dinputd/).

Якщо повторюєш налаштування на іншому ПК, перевіряй кожен етап окремо й записуй версії Windows/програм, PID, осі та їхні значення до і після. Саме ці факти дозволяють відрізнити нову несправність від старого кешу або подвійного вводу.
